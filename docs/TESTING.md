# Testing

Run the suite with `uv run pytest`. The pytest settings in `pyproject.toml`
set `testpaths = ["tests"]` and `pythonpath = ["."]`. The suite needs no API
keys and makes no network calls.

## Patterns

- **Fake the model.** Any object with `bind_tools(tools)` that returns something with `invoke(messages)` will work (see `ToolCallingModel` in `agent.py`). Script its replies as `AIMessage`s. A reply with `tool_calls=[{"name", "args", "id", "type": "tool_call"}]` asks for a tool. Record each call to check the messages that were built, as `RecordingFakeModel` in `test_agent.py` does.
- **Fake OpenWeather.** The `fake_openweather` fixture replaces `weather.fetch_json` with `FakeOpenWeather`. It answers from the sample files and records every request. Use `.requests`, `.geocoded` (the place names sent) and `.weather_requests` to check what went out, and `.api_key` for the fake key it sets. Use `.forecast_requests` for forecast requests. Unknown places geocode to the empty sample. To add a city, add its sample file and an entry in `SAMPLE_PLACES`, plus `SAMPLE_CURRENT_WEATHER` or `SAMPLE_FORECASTS` if it needs weather. The fixture also replaces `weather.utc_now` with `SAMPLE_NOW` (15:00 on Nov 6 in Seattle), so the forecast sample's first day is always "Today".
- **Fake the classifier.** `test_app.py`'s autouse `classifier` fixture replaces `security.create_classifier_model` with a `FakeClassifier` that says YES unless a test queues answers with `classifier.say("off_topic", "YES", …)`. `.calls` and `.requests` record what was sent (`requests[i][1].content` is the data message). `BrokenFakeClassifier` raises like an outage. `no_model_allowed` fails on either model. In `test_classifier.py`, `FakeClassifier(output)` returns any raw `with_structured_output` result, and `answer(parsed, raw, parsing_error)` builds one shaped like LangChain's.
- **Control the rate limiter's clock.** Unit tests pass `RateLimiter(state, clock=FakeClock())` with a plain dict as the state. In app tests, the autouse `app_clock` fixture replaces `security.monotonic_now` with a `PatientClock` that moves 3 s on every reading, so tests that send several messages never hit the cooldown. A cooldown test patches in a plain `FakeClock` instead and calls `clock.advance()`. To test the cap without sending 20 messages, seed `at.session_state[RATE_LIMIT_KEY] = UsageCounters(20, None)` (or loop, as `test_message_21_is_blocked_without_a_grok_call` does).
- **Read the security log.** Take the `security_log` fixture (the temporary log file's path) and call `log_lines(security_log)`. It is `[]` until something is logged. Never point tests at the real `logs/`. An error event spans several lines: its first line, then a stack trace indented by `CONTINUATION_INDENT`. To count events, skip lines that start with a space.
- **Fake xAI failures.** Build the real `openai` exceptions that `ChatXAI` raises with `xai_status_error(cls, status, message)` and `xai_timeout()` from `test_errors.py`. They need an `httpx2` request or response (the `openai` client's HTTP library), and no network call is made. In app tests, `FailingFakeModel(error)` raises one from every call.
- **Fake OpenWeather failures.** `test_weather.py`'s `fail_like_requests(status)` replaces `requests.get` with one whose errors quote the full URL, query string and key, as real `requests` errors do (`None` for a timeout).
- **Stack traces show source code.** A logged stack trace includes source lines such as `"appid": openweather_key()`. Check for values and the query-string form (`appid=`), not bare names.
- **Control the cache's clock.** `test_cache.py`'s `clock` fixture replaces `weather.WEATHER_CACHE` with a `TimedCache(clock=FakeClock())`. Call `clock.advance(seconds)` to jump ahead. Without it, each test still gets an empty cache from `fresh_weather_cache`, so a lookup in one test is never served from another test's cache.
- **Build forecasts by hand.** `test_forecast.py`'s `entry()`, `every_3_hours()` and `forecast()` helpers build OpenWeather-shaped responses for any UTC offset, so expected days can be worked out on paper. Pass `now` to `summarize_forecast()` or `lookup_weather_forecast()` instead of using the real clock.
- **Spy on the tool.** `test_agent_loop.py`'s `tool_ran_for` fixture wraps `weather.lookup_current_weather`, so a test sees every city the tool started for, even one rejected before the network.
- **The HTTP wrapper.** To test `fetch_json()` itself, monkeypatch `requests.get` with a fake that returns an object with `status_code`, `raise_for_status()` and `json()`, or raises a `requests` exception.
- **Fake keys.** Use obviously fake values set with `monkeypatch.setenv`. Constructing `ChatXAI` with a fake key makes no network call.
- **App tests.** In `test_app.py`:
  - The `use_env_file` fixture writes a temporary `.env`, monkeypatches `config.ENV_PATH` and clears `st.cache_resource` before and after each test.
  - To swap in a fake model, monkeypatch `agent.create_model`. This works because `AppTest` re-runs `app.py`, so its `from … import` lines pick up the patched attribute.
  - The `no_model_allowed` fixture fails the test if a model is created.
  - The units toggle is `at.sidebar.segmented_control[0]`. Its `.value` is the units (`"imperial"` or `"metric"`), and `.set_value("metric").run()` switches it. The fake model's `.requests` records the messages sent with each call, to check the history.
  - Inside a chat message, `.metric`, `.text`, `.image`, `.markdown`, `.caption` and `.table` list the card's elements. A table's `.value` is a pandas DataFrame. The forecast uses `st.table`, so `.dataframe` should be empty.
- **Parametrize with ids.** Use `pytest.param(..., id="...")` so each case's name explains the case.
- **Time.** By plan decision, anything time-dependent takes an injectable clock, and no test sleeps.
- **TDD.** At most 3 behaviors per phase, run through the `tdd` skill. The plan's [TDD recommendations](../plans/weather-chatbot.md#tdd-recommendations) list each phase's candidates.

## What tests can't prove

Tests cannot check live Grok or OpenWeather behavior: whether the classifier judges a topic correctly (YES for a follow-up, NO for a poem or 3 weeks out), whether Grok calls the tool, how it words replies and refusals, whether it passes on an OpenWeather error message (such as a refused key), whether it can be talked into repeating its instructions (the canary would catch it), what OpenWeather or xAI really return when they fail, what OpenWeather returns for a real city, or the spinner in a real browser. Those are checked by hand in a running app (`uv run streamlit run app.py`), with the prompts, expected results and pass/fail column in the manual checklist, [TESTING.md](../TESTING.md) at the project root.
